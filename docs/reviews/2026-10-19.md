# KerfGrid review — 2026-10-19

Scope: all application changes since `78f7791`, shared workspace and original
DXF storage, import/reimport, nesting, leads, cut order, G-code, simulation,
LinuxCNC transfer and browser controls. No physical CNC cycle, jog, probe or
ignition was used for acceptance.

## Findings fixed

- Completed-part routing previously ignored the entire obstacle when a rapid
  endpoint overlapped its bounding box. It now routes around conservative
  contour outlines, permits only a short outward departure from the current
  cutout, and checks every route segment. Circle/arc approximations and rounded
  G-code coordinates include conservative clearance.
- Route failure previously emitted a direct rapid with a warning. Safe mode now
  inserts M0 first, including when optional comments are disabled. Simulation
  uses the exported G-code and marks the pause and warned transition.
- Cut-order optimization used straight distances and nominal contour starts.
  It now uses actual pierce/exit coordinates and routed distances, and checks
  whether a selected part would leave a reachable next cut. Ungrouped cuts
  preserve own-hole-before-outer, filler-before-surrounding-hole and manual
  part-order constraints.
- Transfer could report `loaded=true` for a command that exited successfully
  without confirming GUI loading. A matching native-filtered-file receipt is
  now required. The default command checks idle motion and calls the native
  GUI loader; direct NML loading is no longer the default fallback.
- DXF reimport derived quantity from placed instances. Requested quantity is
  now preserved even when placement count differs, including zero quantity.
- Zero-decimal G-code formatting removed significant integer zeroes. Integer
  100 now remains 100. Generated inline comments sanitize parentheses/newlines.

## Reviewed accumulated behavior

- Server-side SQLite workspace uses revisions and transactions; stale browser
  writes preserve the local draft and cannot overwrite newer server state.
- Normal browser, agent and FreeCAD imports preserve source geometry. Original
  uploaded DXFs remain downloadable. Geometry repair remains explicit.
- No sheet-edge margin is introduced; inter-part spacing remains configurable.
- Compact and strip packing use separate consistent objectives. Opposing-pair
  seeds and subsequent compaction retain valid layouts when the budget expires;
  locked placement and exact polygon clearance checks remain in force.
- Leads are checked against retained material, neighbors and sheet bounds.
  Waste-pocket candidates reduce unnecessary extent without moving manual leads.
- Rapid and cut overlays follow the exact generated G-code; traverses are not
  highlighted as already cut material.
- Published files were checked for credential patterns; no candidates were
  found. Workspace databases, temporary output and credentials are excluded.

## Completed-part travel benchmark

Input: the existing 18-tab workshop project, unchanged placements and leads.
The exported G-code was independently checked against previously completed
source polygons, without reusing the route collision predicate.

| Mode | Rapid length | M0 stops | Unpaused part-interior crossings |
| --- | ---: | ---: | ---: |
| Direct | 1672.49 mm | 0 | 13 |
| Safe, 8 mm clearance | 2282.00 mm | 6 | 0 |
| Safe, 2 mm clearance | 2187.62 mm | 0 | 0 |

The project's 8 mm clearance was not reduced. The 2 mm run is a software
comparison, not a measured clearance recommendation. M0 requires clearing the
warned route before resuming; the following direct rapid remains visible in
simulation. This avoids silently claiming an unresolved path is safe.

## Limits

Routing uses cutout footprints and the configured clearance, within sheet
bounds. It cannot predict a part tipping or rotating beyond those footprints,
and cannot eliminate the initial departure from a newly cut slug. A route
complexity limit also produces M0 rather than an unannounced direct move.
Simulation time excludes operator pauses. Review and export warnings remain
non-blocking by contract.

Native LinuxCNC transfer requires the controller-side GUI loader described in
`../contracts/api.md`. Transfer protocol acceptance uses mocks here; real
controller loading and cutting were not replayed during this review.
